# Валидация HTML

Валидация проверяет разметку на соответствие стандарту HTML. Валидный код реже ломается в разных браузерах и проще поддерживается.

## Зачем валидировать

- Найти незакрытые теги и вложенность «не по правилам»
- Убрать устаревшие атрибуты и теги
- Упростить отладку странных багов вёрстки

## W3C Validator

Сервис validator.w3.org принимает URL или вставку кода. Он показывает ошибки и предупреждения с номерами строк.

```html
<!-- Ошибка: div внутри p недопустим -->
<p>
  Текст
  <div>Блок внутри абзаца</div>
</p>
```

## Типичные ошибки новичков

Дублирование id, пропущенный alt, неправильный порядок закрытия тегов — частые находки валидатора.

```html
<!-- Плохо: два одинаковых id -->
<div id="main"></div>
<div id="main"></div>

<!-- Лучше: class для повторяющихся блоков -->
<div class="card"></div>
<div class="card"></div>
```

## Линтеры в редакторе

Расширения вроде HTMLHint или встроенная проверка VS Code подсвечивают проблемы до деплоя.

```html
{
  "tagname-lowercase": true,
  "attr-value-double-quotes": true,
  "id-unique": true,
  "tag-pair": true
}
```

## Валидность и практика

Иногда браузер «прощает» ошибки, но полагаться на это не стоит. Старайся писать разметку, которая проходит валидацию без критических ошибок.

> Валидатор — не цель, а инструмент: он указывает на места, где стандарт и браузер могут расходиться во мнении.

Проверяй HTML после крупных правок и перед релизом — это дешевле, чем искать баг в продакшене.
