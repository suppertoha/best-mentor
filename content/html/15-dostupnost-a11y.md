# Доступность a11y

Доступность (accessibility, сокращённо a11y) — это практика, при которой сайтом могут пользоваться люди с разными возможностями: со скринридером, только с клавиатуры, при низком зрении.

## Семантика и заголовки

Используй один `<h1>` на страницу и не пропускай уровни заголовков без причины. Семантические теги дают контекст assistive technologies.

```html
<main>
  <h1>Личный кабинет</h1>
  <section aria-labelledby="orders-title">
    <h2 id="orders-title">Мои заказы</h2>
    <p>Список последних покупок.</p>
  </section>
</main>
```

## alt, label и aria-label

У изображений — осмысленный alt. У полей формы — связанный `<label>`. Если видимой подписи нет, помогает `aria-label`.

```html
<label for="email">Email</label>
<input id="email" type="email" name="email" autocomplete="email" />

<button type="button" aria-label="Закрыть модальное окно">×</button>
```

## Фокус и клавиатура

Все интерактивные элементы должны быть доступны с Tab. Не убирай outline без замены видимого фокуса.

```css
:focus-visible {
  outline: 2px solid #005fcc;
  outline-offset: 2px;
}
```

## ARIA-роли и состояния

ARIA дополняет HTML, когда семантики не хватает. Не дублируй то, что уже даёт нативный тег.

```html
<div role="alert" aria-live="assertive">
  Не удалось сохранить изменения.
</div>

<button aria-expanded="false" aria-controls="menu-list">
  Меню
</button>
<ul id="menu-list" hidden>...</ul>
```

## Контраст и размер текста

Текст должен читаться на фоне: минимальный контраст для обычного текста — 4.5:1 (WCAG AA). Не полагайся только на цвет для передачи статуса.

- Добавляй иконку или текст к цветовому индикатору
- Проверяй страницу в режиме эмуляции скринридера
- Тестируй навигацию только с клавиатуры

> Доступность — не «фича для немногих», а качество интерфейса для всех пользователей.

Начни с семантики, alt, label и фокуса — это даёт больший эффект, чем сложные ARIA-деревья.
